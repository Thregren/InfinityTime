# 更新日志

## 1.13.0

### 上传与性能

- **上传进度细化**：上传时显示「已上传 / 总大小」（如 `12.3 MB / 48.0 MB`），大图批量上传更直观。
- **峰值内存下降**：生成响应式变体前先释放 GD 位图，8K 全景不再出现「GD 全图 + Imagick 全图」内存叠加。
- **全景不再多下载**：全景的隐藏 `<img>` 跳过 `srcset`，避免「1600 变体 + Pannellum 全图」重复流量。

### 自检与健壮性

- 复查 SQL 参数化、输出转义、路径穿越、CSRF、HTML 清洗、PHP 8.5 兼容，均无新增问题。
- 修复 v1.12.x 发现的 SQLite 事务语句与变体冗余（见 1.12.1）。

## 1.12.1

### 健壮性修复

- **SQLite 兼容**：修复「清理非插件文章」的事务语句——SQLite 只支持 `BEGIN`，原来的 `START TRANSACTION` 会直接语法报错；现在 `BEGIN / COMMIT / ROLLBACK` 在 SQLite 与 MySQL 都可用。
- **变体去冗余**：小于 1600px 的图片不再生成等尺寸的中间副本，避免浪费磁盘。

### 自检

- 主题内联 JS 外置后回归：灯箱、EXIF 侧栏、全景、主题色提取均正常，控制台 0 异常。
- 后台图集按需加载后，展开自动注入图片列表，拖拽排序自动生效。

## 1.7.3

### 修复：灯箱切图顺序
- **根因**：无限瀑布流把卡片按列重排（`.wf-col`），导致 poptrox「上一张/下一张」按**列序**（先一列往下、再下一列）切图，与首页从左到右的阅读顺序不一致。
- **修复**：给每张卡片记录**源码顺序** `data-pp-order`（首个 build 时按 PHP 输出顺序、翻页后继续追加；resize 不覆盖），灯箱改用该顺序切图（按源码顺序从当前图切到相邻的上一张/下一张），不再按瀑布流列序乱跳。无限瀑布流新加载的卡片也计入顺序。

## 1.7.2

### 修复：无限瀑布流新图片未绑定灯箱
- **根因**：poptrox 只在初始化时给锚点绑定点击（并移除其 `href`），无限瀑布流 `fetch` 到第 2 页后 `appendChild` 的新卡片从未被绑定 → 点击直接跳 `.webp` 原图。
- **修复**：翻页后安全重绑一次。关键点：poptrox 只绑定「还有 `href`」的锚点，而早已绑定的卡片 `href` 已被移除，重绑前先从 `data-images[0]` **补回 `href`**，否则重绑会跳过旧卡片导致「所有灯箱打不开」（此前的回退正是咬在这一步）。
